# M3.7 — Campground Detail Final QA

## Goal
Close M3 with a regression pass across the complete public campground detail experience built in M3.1–M3.6.

## Test target
Use the fictional QA campground:
- slug: `icl-qa-m3-detail`
- route: `/camping/icl-qa-m3-detail`

Prerequisites:
1. `supabase/fixtures/m3_detail_qa.sql`
2. `supabase/fixtures/m3_5_gallery_qa.sql`
3. `supabase/fixtures/m3_6_trust_qa.sql` (default fresh scenario)

## Build gate
Run:

```bash
npm run build
```

Expected: production build completes without TypeScript/build errors.

The known `controller[kState].transformAlgorithm is not a function` error observed under `next dev` remains a separate dev-runtime hardening item. It must not be marked resolved merely because the production build passes.

## Desktop QA
Verify:
- detail route returns the fictional campground, not 404;
- hero cover renders;
- campground name, location, type, and verification badge render;
- short and long descriptions render without literal escape text;
- elevation, capacity, access, and type facts render;
- facilities and facility notes render;
- vehicle access and notes render;
- suitable-for labels render;
- check-in and good-to-know render;
- all 6 active QA prices render and inactive QA price does not;
- all 5 public QA contacts render and private QA contact does not;
- primary contact CTA works;
- 5-photo gallery renders;
- gallery lightbox opens, previous/next works, Escape/close works;
- OSM basemap renders;
- campground marker renders at the fixture coordinates;
- directions CTA opens an external map target;
- trust panel renders verification status, date, and freshness copy;
- sticky summary remains usable;
- related campground cards render when available.

## Mobile QA
Verify at a narrow viewport:
- header and page do not overflow horizontally;
- hero content remains readable;
- facts use a usable 2-column layout;
- price/contact cards fit the viewport;
- gallery remains usable;
- lightbox image and controls remain reachable;
- map renders and zoom controls remain reachable;
- trust panel is readable without horizontal overflow;
- CTA buttons remain tappable.

## Trust regression scenarios
Use `supabase/fixtures/m3_6_trust_qa.sql` and run one scenario at a time.

Expected states:
- Fresh + Verified: `Terverifikasi ICL` + `Data masih baru`, no confirmation warning.
- Aging + Community Updated: `Diperbarui komunitas` + `Sebaiknya konfirmasi kembali`, confirmation warning visible.
- Stale + Needs Update: `Perlu diperbarui` + `Data sudah cukup lama`, confirmation warning visible.
- Unknown + Needs Update: `Perlu diperbarui` + missing-date message, confirmation warning visible.

After scenario testing, restore Scenario A (Fresh + Verified).

## Security/privacy regression
Public detail must not expose:
- `verified_by`;
- internal verification notes;
- moderator notes;
- private contacts;
- inactive prices;
- pending/rejected photos.

M3.6 requires no RLS/grant relaxation.

## Exit criteria
M3 can be marked COMPLETE when:
1. production build passes;
2. desktop QA passes;
3. mobile QA passes;
4. all four trust states behave as specified;
5. no M3.1–M3.5 regression is found;
6. private/internal fields remain hidden.

Any failure is fixed on `develop` before M3 is closed. Do not merge `develop` into `main` as part of this QA without explicit approval.
