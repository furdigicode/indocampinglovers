# M5.2 — Controlled Submission API Test

Run after migrations 0009 and 0010, with `NEXT_PRIVATE_SUPABASE_SECRET_KEY` configured locally.

## 1. Resolve test geography IDs

Open `/api/health/supabase` only for connectivity. For the POST body, use real province/regency UUIDs from the public database. The upcoming M5.3 wizard will resolve these automatically.

## 2. Valid request

Send JSON to `POST /api/submissions/campgrounds`:

```json
{
  "name": "ICL M5 API Test Camp",
  "provinceId": "<JAWA_TENGAH_UUID>",
  "regencyId": "<KABUPATEN_SEMARANG_UUID>",
  "address": "Alamat fiktif untuk QA M5.2",
  "submitterName": "ICL QA",
  "submitterContact": "qa@example.invalid",
  "consent": true,
  "idempotencyKey": "icl-m5-qa-00000001"
}
```

Expected: HTTP 201, `ok: true`, and an `ICL-XXXXXXXX` reference.

## 3. Duplicate request

Repeat the exact request.

Expected: HTTP 200, same reference code, `duplicate: true`. There must still be only one database row for that idempotency key.

## 4. Invalid geography

Use the Jawa Tengah province UUID with a regency UUID belonging to another province.

Expected: HTTP 400 and no submission row.

## 5. Invalid consent

Set `consent: false`.

Expected: HTTP 400 and no submission row.

## 6. Database verification

```sql
select reference_code, status, idempotency_key, submitter_name, created_at
from public.campground_submissions
where idempotency_key = 'icl-m5-qa-00000001';
```

Expected exactly one row, status `pending`.

## Cleanup
